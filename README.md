# Fusion

A typed drop-in layer over React. Agents write completely normal React, imported
from `"react"`; Fusion makes the wrong things fail to compile, and the compiler
error says what to write instead.

```tsx
import { useEffect } from "react";

useEffect(() => track(user), [{ id: user.id }]);
//                            ~~~~~~~~~~~~~~~~
// Type '{ id: string; }' is not assignable to type '"Dependency is not stable:
// it can change identity every render, so this effect can re-run every render.
// Wrap it in useMemo/useCallback, or depend on a primitive (e.g. user.id)
// instead. If it is a prop, type the prop as Stable<T>. If a library keeps it
// stable, use unsafeStable(value, reason)."'.
```

The design is in [docs/SPEC.md](docs/SPEC.md). Status: Phase 1. The shim, its
resolution for TypeScript and Vite, Rule 1 (stable dependencies) and Rule 2
(stable context values) are implemented. The ESLint guard rail is not; the
Vite plugin enforces the same restriction at build time.

## Using it in a project

Two lines of configuration, no source changes. See [examples/basic](examples/basic).

```jsonc
// tsconfig.json
{ "extends": "fusion/tsconfig" }
```

```ts
// vite.config.ts
import fusion from "fusion/vite";
export default defineConfig({ plugins: [fusion(), react()] });
```

`fusion/tsconfig` only sets `compilerOptions.paths`. A project that defines its
own `paths` replaces that object, so it has to copy the two entries from
[fusion/tsconfig.preset.json](fusion/tsconfig.preset.json).

## The rules

1. **Stable dependencies.** A dependency array (`useEffect`, `useLayoutEffect`,
   `useInsertionEffect`, `useImperativeHandle`, `useMemo`, `useCallback`) only
   accepts stable values.
2. **Stable context values.** A context provider's `value` must be stable, for
   both `<Ctx.Provider value>` and `<Ctx value>`.

## What counts as stable

| Value | Why it is stable |
|---|---|
| Primitives | Compared by value |
| `useState` / `useReducer` state | Keeps its identity until it is set |
| `useState` setter, `useReducer` dispatch, `startTransition` | Guaranteed by React |
| `useRef` result | Same object every render |
| `useMemo` / `useCallback` result | Typed as `Stable<T>`; their own deps are checked too |
| `useContext` / `use(Context)` result | Rule 2 guarantees the provided value is stable |
| `stable(x)` | Explicit, for values created outside render (module constants) |
| `unsafeStable(x, reason)` | Escape hatch, see below |
| Anything typed `Stable<T>` | E.g. a custom hook's declared return type, or a prop |

`Stable<T>` is `T` plus a compile-time brand, so a stable value can be used
anywhere a `T` is expected. `stable`, `unsafeStable` and `Stable` are imported
from `"react"`.

**Props.** An object or function prop is not known to be stable, so it cannot
be a dependency as is. A component that depends on one says so in its props
type, which makes the parent pass a stable value:

```tsx
function Profile({ user }: { user: Stable<User> }) {
  useEffect(() => track(user), [user]);
}
```

**Escape hatch.** For a value Fusion cannot see into, typically the result of
a third-party hook that documents a stable return value, `unsafeStable` asserts
stability and records why. The reason is required.

```tsx
const navigate = unsafeStable(useNavigate(), "react-router keeps navigate stable");
```

**Stability is shallow.** `user` from `useState` is stable, but `user.address`
is not typed as stable. Depend on the whole value or on a primitive field.

## How it works

- `fusion/types/react.d.ts` is what TypeScript sees for `"react"`: the same
  `export =` namespace shape as `@types/react`, with every name passed through
  by alias (so types keep their identity and `declare module "react"`
  augmentations still work) except the hooks Fusion redefines.
- `fusion/src/react.ts` is what Vite serves for `"react"` in application code.
  The redefined hooks are the real React functions with different types, so
  there is no runtime wrapper and no overhead.
- Both files are generated by `fusion/scripts/generate.mjs`, because
  `@types/react` uses `export =`, which cannot be re-exported with `export *`.
- `fusion/src/hooks.ts` holds the redefined hook signatures,
  `fusion/src/context.ts` the context rule, `fusion/src/stable.ts` the brand,
  and `fusion/src/errors.ts` the dependency error messages.
- A Fusion context is a plain React context whose value type is the stable
  form of `T`, so `useContext`, `use`, `ContextType` and class `contextType`
  work unchanged.
- `fusion/vite.ts` redirects the exact specifier `react`, for application code
  only. Subpaths (`react/jsx-runtime`), `react-dom` and everything in
  `node_modules` keep resolving to real React, and share one copy of it with
  the shim. It also rejects imports of the private `fusion-react-original`
  specifier from outside Fusion.

## Development

```sh
pnpm install
pnpm check        # generated files up to date, type tests, runtime tests
pnpm generate     # regenerate the shim after changing React or src/hooks.ts
pnpm dev          # run examples/basic
```

- `fusion/tests/types/` are the type tests: `*.fail.tsx` holds one
  `@ts-expect-error` per case that must not compile, the rest must compile
  cleanly. `upstream-drift.ts` pins the `@types/react` signatures Fusion
  replaces, so a React upgrade that changes one fails the type check.
- `fusion/tests/runtime/` checks that the shim is identical to React at runtime,
  and checks the exact text of the error messages.
- `examples/basic/tests/` checks Vite resolution and that the production bundle
  contains one copy of React.

Supported versions: React and `@types/react` 19.3, TypeScript 7, Vite 8.
